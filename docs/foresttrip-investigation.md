# 숲나들e 실제 조회 구조 조사

조사일: 2026-09-09 (한국/일본 표준시)

## 현재 결론

**1단계 핵심 조회 구조 분석 완료 — 2026-09-09 인증된 직접 HTTP에서 지역·객실·상세 요금 응답과 2박 조회를 재현했다. MVP 구현을 시작한다.**

비로그인 요청은 HTTP **401 Unauthorized**를 반환한다. 사용자 로그인 및 로컬 세션 사용 승인 후 동일 내부 조회가 200으로 성공했다. 아래 1~8절은 비로그인 단계 기록이며, 최신 확인 결과는 9~10절에 있다. 인증 실패를 빈방 0건으로 해석해서는 안 된다.

UI보다 실제 조회 분석을 먼저 수행했다. 저장된 JSON/HTML은 실제 HTTP 응답이며 가상 객실 자료가 아니다.

## 1. 공식 API 우선 검토

- [산림청_국립자연휴양림 예약정보](https://www.data.go.kr/data/15134227/openapi.do?recommendDataYn=Y)
- 포털은 REST/XML, 활용신청 필요, 개발계정 1,000건 트래픽을 안내한다.
- 업데이트 주기는 실시간으로 표시되지만 본문은 **2023-03-15~2024-02-28 예약 현황**을 설명한다. 국립 범위이며, 전 국·공·사립의 현재 예약 가능 객실/정원/가격을 제공한다는 명세는 확인되지 않았다.
- 따라서 이 API를 현재 재고 API라고 단정하거나 MVP에 바로 연결하지 않는다. 제공 범위와 최신 명세를 추가 확인해야 한다.

## 2. 브라우저 재현 절차 및 Network 관찰

Chrome에서 [숲나들e 메인](https://www.foresttrip.go.kr/main.do)에 접속했다.

1. 지역 → `서울/인천/경기` 선택.
2. 휴양림 → `(가평군)유명산자연휴양림` 선택.
3. 날짜 → `2026-09-19` 입실, `2026-09-20` 퇴실 선택 → 확인.
4. 인원 기본값 `2` 확인.
5. 개발자 도구 Network 기록 및 로그 보관을 켜고 조회 실행.
6. `fcfsRsrvtPssblGoodsDetls.do` 문서 요청 확인.
7. 요청 헤더의 메서드 GET, 응답 401 Unauthorized, Content-Type `text/html;charset=UTF-8` 확인.
8. 화면은 `로그인하시고 다양한 서비스를 이용해 보세요.` 및 로그인 폼을 표시.

응답 Date: `Wed, 09 Sep 2026 01:33:01 GMT`.

사이트 자체 `NetFunnel_Action`이 생성한 대기열 키와 메인 세션의 CSRF 값이 포함된 요청이었다. 단순 HTTP 요청의 키 누락 문제만으로 설명되지 않는다. 비로그인 상태의 객실 조회가 인증을 요구한다는 것이 이 재현에서 확인된 범위다. 로그인 사용자에게 어떤 조회 응답이 제공되는지는 아직 미확인이다.

Codex 내장 브라우저에서는 메인 접속이 오류 화면으로 전환되었으나, Chrome과 직접 HTTP의 메인 접속은 성공했다. 내장 브라우저 오류를 사이트 전체 장애로 판단하지 않았다.

## 3. 확인한 HTTP 주소

기준 호스트: `https://www.foresttrip.go.kr`

| 용도 | 메서드/경로 | 확인 결과 |
| --- | --- | --- |
| 메인/검색 폼 | GET `/main.do` | 200, HTML/인라인 JavaScript |
| 지역 목록 | GET `/rep/or/selectSiDoList.do` | 200, JSON 배열 |
| 지역별 휴양시설 목록 | GET `/rep/or/selectInsttListForSearch.do?srchSido=1` | 200, `{insttList:[...]}`, 25개 시설 |
| 달력 기본 정보 | GET `/com/selectTodayCalendar.do` | 메인 JS에서 호출 확인; 응답 필드 미분석 |
| 휴양림별 달력 정책 | GET `/rep/or/selectFcFsRcfrsFcltInfo.do?insttId=...` | 메인 JS에서 호출 확인; 응답 필드 미분석 |
| 지역 통합 검색 | GET `/rep/or/fcfsRsrvtRcrfrDtlDetls.do` | 메인 폼 분기에서 확인; 직접 요청은 alert 페이지로 전환 |
| 휴양림 객실 검색 | GET `/rep/or/sssn/fcfsRsrvtPssblGoodsDetls.do` | Chrome 정상 검색에서 401 + 로그인 HTML |
| 월별현황 | GET `/rep/or/sssn/monthRsrvtStatus.do` | 직접 요청 401 + 로그인 HTML |

목록 AJAX는 `type: 'get'`, `dataType: 'json'`, `X-Ajax-call: true`를 사용한다. 직접 목록 HTTP 조회는 인증 쿠키 없이도 성공했다. 예약·결제·관심상품 등록 등의 변경 요청은 실행하지 않았다.

| `rsrvtPssblYn` | `N` | 메인 폼 기본값. **개별 객실의 예약 불가 판정값이 아님** |

## 5. 목록 응답과 지역 정규화 주의점

지역 응답은 `detailCode`, `arcd`, `codeNm`, `codeDc` 등을 포함한다.

| 원본 코드 | 원본 지역명 |
| --- | --- |
| 1 | 서울/인천/경기 |
| 2 | 강원 |
| 3 | 충북 |
| 4 | 대전/충남 |
| 5 | 전북 |
| 6 | 전남광주 |
| 7 | 대구/경북 |
| 8 | 부산/경남 |
| 9 | 제주 |

경기 검색에 원본 코드 1을 그대로 쓰면 서울·인천 시설이 섞인다. 시설의 공식 주소/시도 데이터를 확보해 실제 경기만 후처리해야 한다. 시군 이름만으로 불확실한 시도를 추측하지 않는다. 전국 검색은 원본 지역 목록을 이용하되 중복 시설을 ID로 제거해야 한다.

휴양시설 목록의 최상위 키는 `insttList`다. 실제 관찰한 예:

```json
{
  "insttId": "0101",
  "insttNm": "(가평군)유명산자연휴양림",
  "insttTpCd": "01"
}
```

코드 1 응답에는 25개가 있으며 자연휴양림 외 야영장 등도 포함된다. 숙박시설 분류로 범위를 제한해야 한다. 공식 화면은 `insttTpCd` 01/02/04를 국립/공립/사립으로 표시한다.

목록 객체에 `rsrvtAvail`, `rsrvtCnt`, `goodsId`, `mnmmAccptCnt`, `mxmmAccptCnt` 같은 이름도 존재하지만 이 응답에서는 null이다. 공유 데이터 객체의 필드명만 보고 빈방 상태/정원 의미를 확정할 수 없다.

## 6. 아직 확인되지 않은 핵심 항목

- 로그인 뒤 발생하는 객실 목록 XHR/HTML 주소와 요청 규칙.
- 확정 예약 가능/예약대기/추첨/우선예약/운영중단을 구별하는 필드와 실제 값.
- 체크아웃 전 모든 숙박일에 **동일한 객실**이 예약 가능해야 한다는 판정 방식.
- 가격이 1박인지 전체 기간 합계인지, 날짜별 요금과 추가 인원 요금의 처리.
- 기준/최대 인원, 공식 주소, 시설 분류의 정확한 원본 필드.
- 페이지 처리, 전체 건수 및 지역 단위 일괄조회 가능 범위.
- 로그인/대기열 세션을 정상 유지하면서 서버 HTTP 조회를 재현할 수 있는지.
- 객실/휴양림 예약 연결 주소의 안정성. 인증·대기열 키는 예약 URL에 저장하면 안 된다.

이 항목을 실제 응답으로 검증하기 전에는 정규화 매핑과 수집기 구현을 확정하지 않는다.

## 7. 조사 재개 후 구현 기준

1. 사용자가 Chrome 공식 사이트에 직접 로그인한다. 비밀번호/쿠키를 채팅이나 소스 파일로 받지 않는다.
2. 동일 조건으로 공식 검색을 다시 실행하고 Network에서 객실 응답을 확인한다. 인증 요청이나 개인정보는 분석 산출물에 저장하지 않는다.
3. 공식 API → 공개 웹 조회 주소 → HTML 파싱 순서로 실제 HTTP 재현성을 검증한다. 인증 필요/접근 제한을 우회하지 않는다.
4. 실제 응답의 원본 필드와 정규화 스키마 매핑, 기간 전체 예약 가능 조건을 이 문서에 추가한다.
5. 조사 완료 후 수집 → 정규화 → 검색 API → 반응형 UI를 구현한다. Mock 객실은 사용하지 않는다.
6. 병렬 요청 상한, timeout, 제한적 retry, 조건별 짧은 캐시와 중복 요청 병합을 적용한다. 401/403은 재시도하지 않고 인증 문제로 분리하며, 429의 Retry-After를 존중한다.
7. 조회/파싱/스키마 오류와 마지막 성공 시각을 기록한다. 일부 조회 실패 시 전체 조회 완료로 표시하지 않는다.
8. 경기+강원, 2026-09-19~20, 2명으로 실제 검색 → 객실/정원/가격 → 공식 예약 연결까지 검증한다. 결과가 실제로 0개라면 0개로 보고하며 예시 37개를 만들지 않는다.

## 9. 로그인 후 후속 조사 (2026-09-09 10:39~10:48 KST)

### 실제 관찰 결과

- 수도권 원본 그룹: 25개 휴양시설, 양평설매재 4개 및 청평 2개의 예약 가능 객실 표시.

- 청평: `[가족 · 친구 · 연인]S-6(2인용) 침대룸`, 기준/최대 2/2, 1박 주말 140,000원. 객실 ID `GID040300070100301005001000020`.
- 강원 원본 그룹: 31개 휴양시설. 예약 가능 객실 수는 횡성 17, 삼척활기 9, 피노키오 9, 검봉산 8, 가리왕산 3, 두타산 2, 미천골 1로 표시되었다.
- 검봉산 객실 `[연립동][A동]고로쇠`: 객실 ID `G02440100301003007900132`, 기준/최대 8/8명. 상세 영역에서 숙박기간 `2026.09.19~2026.09.20 (1박2일)`, 날짜별 요금 `2026.09.19(비수기/주말) 173,000원`, 합계 `173,000원`을 확인했다.

이 수치는 조사 시점의 공식 화면 관찰이며 완성된 서비스 검색 결과나 고정 재고가 아니다.

### 확인한 내부 조회 요청

세 주소 모두 공식 페이지 소스가 `POST`, JSON body, `X-Ajax-call: true`, `X-CSRF-TOKEN` 세션 토큰을 사용한다.

1. `/rep/or/innerFcfsRcrfrDtlDetls.do`: 지역별 휴양시설과 예약 가능 객실 수를 담은 HTML.
2. `/rep/or/sssn/innerFcfsRsrvtPssblGoodsDetls.do`: 휴양림별 객실 목록 HTML.
3. `/rep/or/innerFcfsRsrvtPssblGoodsDtl.do`: 객실 상세/날짜별 요금 JSON. 검봉산 공식 화면에서 이 요청으로 채워지는 상세/합계 표시까지 관찰했다. JSON 원문 자체의 서버 HTTP 재현은 진행 중이다.

객실 목록 요청의 최소 검증 대상 payload:

```json
{
  "srchInsttId": "ID04030007",
  "srchRsrvtBgDt": "20260919",
  "srchRsrvtEdDt": "20260920",
  "srchStngNofpr": "2",
  "srchSthngCnt": 1,
  "houseCampSctin": "01",
  "rsrvtWtngSctin": "01",
  "gNowPage": "1",
  "srtngOrdr": "goodsClsscCd",
  "goodsClsscHouseCdArr": [],
  "allNanChkGoodsClssCd": "N"
}
```

`goodsClsscHouseCdArr`와 `allNanChkGoodsClssCd` 조합은 실제 전체 숙박 분류 선택 상태로 재현해 확인해야 한다. 무작정 빈 배열을 보내 전체라고 가정하지 않는다.

객실 상세 payload는 `srchInsttId`, `srchGoodsId`, `srchRsrvtBgDt`, `srchRsrvtEdDt`, `srchStngNofpr`, `srchSthngCnt`이다.

### 예약 가능과 대기 구분

- 공식 페이지 `fn_goSrch()`에서 대기 보기 체크 해제 시 `rsrvtWtngSctin=01`, 체크 시 `02`를 전송한다.
- 따라서 HTML의 객실 존재 여부만 보지 않고 **01 조건으로 조회한 성공 응답에 포함된 객실**인지 확인해야 한다.
- 목록 `.communication_list .list_box > a.item[data-value]`의 `data-value`가 객실 ID다.
- `.opt1`은 이름/분류, `.opt2`는 기준/최대 인원과 면적, `.opt3`는 표시 요금이다.
- `type01` 클래스와 `사용가능 시설` 텍스트만으로 예약 가능을 판단하면 안 된다. `사용가능 시설`은 에어컨 등 편의시설 아이콘의 접근성 라벨이다.
- `.page_list .paging_count`는 `(현재/전체 페이지)`를 표시하며 청평은 `(1/1)`이었다. 1페이지만 조회하고 전체 조회로 표시하지 않는다.
- 전체 기간 조건을 서버에 전달하며, 추가로 날짜별 숙박일/가격 목록이 체크인 이상 체크아웃 미만의 모든 날짜와 일치하는지 검증해야 한다. 다박 실제 응답 확인은 아직 남아 있다.

### 발견한 데이터 품질/수집 주의사항

1. 원본 수도권 결과의 양평설매재 주소가 서울 동작구 사무국 주소로 표시된다. 원본 주소의 시도만 필터링하면 경기 숙소를 놓친다. 휴양림 실제 소재지 필드/공식 시설 소개를 확인해 교차 검증해야 한다.
2. 원본 지역 검색은 숙박 `01`로 조회해도 휴양림 상세 진입 시 숙박/야영 전체가 선택될 수 있다. 검봉산 목록에서 숙박 8개 외 야영데크도 함께 표시됐다. API 수집에서 숙박 상위 분류를 명시하고 상세 응답으로 재검증해야 한다.
3. 개별 객실 페이지에 `detectDevTool()`이 있으며 개발자 도구가 열리면 `debugger` 일시중지 후 메인으로 이동한다. 이를 비활성화하거나 우회하지 않았다. 이미 수신된 Network 원문을 저장하고 도구를 닫아 정상 화면 조사를 계속했다.
4. 새 비로그인 세션의 쿠키/정상 CSRF 토큰을 받아 동일한 객실 목록 POST를 실행해도 HTTP 401, `ErrorCode=-5`, 로그인 세션 관련 오류를 반환했다. 브라우저 화면만의 로그인 확인이 아니라 서버 조회에도 인증 세션이 필요하다.

### 구현 방향

지역 요청(최대 9개, 동시성 제한) → 실제 소재지/숙박 필터 → 빈방이 있는 휴양림만 객실 페이지 조회 → 상세 가격/정원/기간 검증 → 정규화 결과 API 순서가 적합하다. 서버에서 인증 세션을 정상 이용하는 HTTP 재현을 우선한다.

운영자 세션은 브라우저 로그인 권한과 구분해 다뤄야 한다. 사용자가 로컬 검증용 세션 사용을 승인했다. 인증 쿠키를 공개 소스·프론트엔드·외부 호스팅에 올리지 않는다. 공개 서비스 운영용 인증 방식은 별도로 확정해야 한다.

## 10. 직접 HTTP 검증 완료

로그인된 `/main.do` 요청 **1건만** HAR로 로컬 보관했다. Cookie/CSRF는 출력하지 않으며 파일 권한 0600, research 제외 규칙을 적용했다. 임시 HAR 민감정보 내보내기 설정은 해제했고 개발자 도구를 닫았다. 사이트의 개발자 도구 감지 및 대기열 코드는 수정하지 않았다.

- 지역 내부 POST: 경기 원본 그룹 25개, 강원 31개 HTML, 각각 HTTP 200.
- 검봉산 객실 내부 POST: `houseCampSctin=01`, `rsrvtWtngSctin=01`, 빈 분류 배열/`allNanChkGoodsClssCd=N`으로 숙박 **8개**, 야영 없음. 실제 숙박 분류 배열을 전달한 결과와 8개 ID가 동일했다.
- `POST /rep/cm/selectGoodsClsscList.do`, body `[{trgtObj:"objGsrm",codeId:"0244",upperDetailCode:"01"}]`: `01001=숲속의집`, `01003=연립동`, `01002=휴양관`. 상세 `listGoodsUnprc[].goodsClsCd`에 해당 코드가 있다. 시설별 분류 목록은 별도 조회한다.
- 9명 검봉산, 2명 유명산: 각각 200, 객실 0개, `.paging_count=(0/0)`. 정상 빈 결과에도 `검색결과가 없습니다` 텍스트는 없으므로 페이징/목록 구조를 함께 검사해야 한다.
- 검봉산 `[A동]고로쇠` 상세: `upperGoodsClsscCd=01`, 기준/최대 8/8, 20260919~20260920, `sthngQnt=1`, `sumGoodsUnprc=173000`.
- **2박 검증**: 같은 객실이 20260919~20260921의 일반예약 목록에 포함. 상세 날짜별 `20260919=173000`, `20260920=98000`, 합계 **271000**, `sthngQnt=2`. 일박 단가에 박수를 곱하지 않는다.
- 예약가능 판단: 전체 기간 일반예약 목록에 포함된 동일 ID + 상세 날짜/숙박일별 ID/정원 일치 + 숙박분류 + 가격 합계 일치. 상세 API는 요금 조회이며 단독으로 재고 증명이 되지 않는다.
- 양평설매재 공식 홈페이지 `https://snrf.foresttrip.go.kr`의 메타 설명에서 **경기도, 양평군**을 확인했다. 지역 응답의 사무국 주소 오류는 이 출처에 근거한 명시적 소재지 보정으로 관리한다.

서비스는 로컬 인증 세션을 사용하는 형태로 구현했다. 외부 공개 배포/다중 사용자 운영은 이번 개인 세션 승인에 포함되지 않는다. 실제 전체 서비스 통합검색 결과는 [인수 검증 기록](acceptance.md)에 남겼다.
