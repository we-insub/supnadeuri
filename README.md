# Supnadeuri · 숲 빈방 — 개인 컴퓨터용 실데이터 MVP

**각자 내려받아 자기 컴퓨터에서 실행하고, 본인의 숲나들e 로그인으로 사용하는 프로그램입니다.** 공용 웹사이트·공용 계정 방식이 아닙니다. GitHub에는 코드와 사용법만 공유하며 인증은 사용자별 컴퓨터에 따로 보관합니다.

실제 숲나들e 응답으로 날짜·복수 지역·인원에 맞는 예약 가능한 숙박 객실을 조회합니다. 운영 검색에 Mock 결과나 샘플 빈방을 반환하는 경로는 없습니다.

## 처음 사용하는 분: Mac / Windows

Mac과 Windows용 실행 파일을 제공합니다. Node.js **22.13 이상**과 npm이 필요합니다. [Node.js 공식 사이트](https://nodejs.org/)에서 운영체제에 맞는 버전을 설치한 뒤 실행 창을 다시 열어 주세요. 의존성은 각 운영체제에서 새로 설치해야 하므로 다른 컴퓨터의 `node_modules`나 `dist` 폴더를 복사하지 마세요.

| 작업 | Mac | Windows |
| --- | --- | --- |
| 프로그램 실행 | 숲빈방 실행.command | 숲빈방 실행.cmd |
| 본인 인증 연결 | 숲빈방 인증 연결.command | 숲빈방 인증 연결.cmd |

Windows 대상 환경은 Windows 11 64비트, 기본 Windows PowerShell과 일반 사용자 계정입니다. Windows PowerShell은 운영체제 인증 암호화에 사용되며 관리자 실행이나 실행 정책 해제가 필요하지 않습니다. **GitHub의 macOS·Windows 환경에서 설치, 자동 테스트, 빌드, 검색 화면 HTTP 실행 검사가 모두 통과했습니다.** Windows 자동 검사는 GitHub 호스팅 환경에서 수행했으며 개인 Windows 11 PC의 더블클릭 실행·Chrome 로그인·실조회까지 검증한 것은 아닙니다.

1. GitHub의 **Code → Download ZIP** 또는 제공된 소스 묶음을 내려받아 압축을 풉니다. 다른 사람의 사용 중인 폴더 전체를 복사받지 마세요. 인증이 포함될 수 있습니다.
2. 표에서 운영체제에 맞는 **숲빈방 실행** 파일을 실행합니다. 최초 실행 시 필요한 구성요소를 설치하고 검색 화면을 준비합니다. 실행 창은 닫지 않습니다. Windows에서는 ZIP을 먼저 완전히 풀고 `.cmd`를 실행합니다.
3. Chrome에서 [검색 화면](http://127.0.0.1:3000/)을 엽니다. 이 주소는 각자의 컴퓨터를 가리키며 다른 사람의 프로그램에 접속하는 주소가 아닙니다.
4. 화면의 **숲나들e 로그인**을 누르고 새 Chrome 창에서 본인 계정으로 로그인한 뒤, 검색 화면으로 돌아와 **로그인 완료·연결**을 누릅니다. 기존 인증이 있으면 **숲나들e 다시 로그인**으로 표시됩니다.
5. 날짜·지역·인원을 선택하고 **빈방 찾기**를 누릅니다. 같은 휴양림의 객실은 한 카드 안에 모아 표시됩니다.

출처를 확인한 실행 파일만 사용하세요. 운영체제 보안 설정을 일괄 해제하지 않습니다. Mac 실행 권한 문제가 있을 때는 해당 파일의 권한만 확인합니다. Windows 파일 확장명이 숨겨져 있다면 탐색기에서 확장명을 표시하고 `.cmd` 파일을 선택하세요. 프로젝트는 본인 PC의 개인 폴더에 풀고 공유 드라이브·다른 사람의 인증 폴더는 사용하지 않습니다.

### 버튼으로 본인 로그인 연결

1. 검색 화면의 **숲나들e 로그인 / 숲나들e 다시 로그인**을 누릅니다.
2. 프로그램이 여는 별도 Chrome 창에서 공식 사이트의 로그인을 직접 완료합니다. 본인인증·보안문자도 직접 처리합니다.
3. 검색 화면으로 돌아와 **로그인 완료·연결**을 누릅니다. 본인 로그인 정보만 로컬에 저장하고 검색 캐시를 초기화합니다. 프로그램 재시작은 필요 없습니다.
4. **빈방 찾기**로 실제 조회를 확인합니다. 저장 성공과 원본 조회 성공은 구분해서 표시됩니다.

Mac·Windows에 설치된 Google Chrome을 사용합니다. 평소 Chrome 프로필이나 다른 사이트의 로그인 정보에는 연결하지 않습니다. 이 로그인 창은 임시 전용 창이며 완료·취소 또는 10분 후 닫힙니다. 사용자가 누르기 전에 자동으로 로그인 창을 열거나 인증을 가져오지 않습니다. 비밀번호 입력·자동 로그인·보안문자 풀이·접근 제한 우회는 구현하지 않습니다.

공식 사이트가 이 전용 창을 거부하면 연결할 수 없습니다. **새 로그인 방식의 자동 테스트와 실제 사람의 공식 로그인 완료·실조회 성공은 별개의 검증입니다.** 현재 새 창에서의 본인 로그인 후 최종 실조회 확인이 필요합니다.

로그인 작업 중에는 검색 및 다른 로그인 작업을 막습니다. 버튼 요청에는 같은 로컬 출처와 실행할 때 생성한 검증값이 필요하며, 로그인 비밀은 웹 응답·주소·로그에 포함하지 않습니다. 서버에 인증을 외부에서 업로드하는 공개 API가 아닙니다. 외부 서버에 배포해 여러 사용자가 공유하는 구조는 제공하지 않습니다.

기존 설치를 업데이트할 때는 먼저 실행을 종료하고 `app` 폴더에서 `npm ci`를 한 번 실행해 추가된 로그인 구성요소를 설치하세요. 신규 설치는 실행기가 구성요소를 설치합니다.

### 고급 사용자용: 기존 HAR 수동 연결

평소 사용하던 Chrome 창에 로그인하는 것만으로 프로그램이 연결되지는 않습니다. 일반 사용자는 위 버튼 방식을 사용하세요. 아래는 기존 수동 도구를 유지하기 위한 고급 절차이며, 접근 제한을 우회하기 위한 대체 방법이 아닙니다.

1. Chrome에서 [숲나들e 공식 사이트](https://www.foresttrip.go.kr/main.do)에 **본인 계정으로 로그인**합니다.
2. 로그인한 메인 화면의 요청을 브라우저 Network에서 확인하고, **GET /main.do / 응답 200 한 건만** HAR로 저장합니다. 쿠키와 메인 화면 응답이 포함되어야 하며, 다른 요청은 포함하지 않습니다. Chrome 버전에 따라 내보내기 메뉴 이름이 다릅니다.
   - 메인 요청만 보이도록 필터링하고 실제 내보낼 요청이 한 건인지 확인하세요.
   - 민감정보 포함 내보내기 옵션이 필요한 경우, 본인 컴퓨터에 저장할 때만 사용하고 저장 후 즉시 해제합니다.
   - **개발자 도구 감지나 접근 제한 안내가 나타나면 감지 기능을 끄거나 우회하지 말고 작업을 멈춥니다.** 이 경우 현재 연결 방식의 제약으로 정상 인증 연결을 완료하지 못할 수 있습니다.
3. 실행 중인 숲 빈방 창을 종료합니다. 운영체제에 맞는 **숲빈방 인증 연결** 파일을 실행합니다. Mac은 본인의 HAR 파일을 창에 끌어다 놓고, Windows는 탐색기의 **경로로 복사**로 얻은 전체 경로를 붙여 넣은 뒤 Enter를 누릅니다. 경로를 감싼 따옴표와 한글·공백을 처리하며 입력을 명령으로 실행하지 않습니다. 빈 Enter를 누르면 취소합니다.
4. 연결 성공 안내를 확인한 뒤 운영체제에 맞는 **숲빈방 실행** 파일을 다시 실행합니다. 프로그램을 다시 켜면 이전 인증으로 조회한 메모리 캐시도 초기화됩니다. Windows에서 종료할 때는 Ctrl+C를 사용하고 배치 종료 확인이 나오면 Y를 선택합니다.
5. 실제 검색으로 확인합니다. 화면의 “인증 파일 연결됨”은 파일 확인 결과이지, 숲나들e 로그인 유효성 보장은 아닙니다.

명령줄을 사용하는 경우:

```sh
cd app
npm run session:import -- /absolute/path/to/your-main-request.har
```

연결 도구는 8MB 이하의 메인 GET 요청 1건만 받아 쿠키/CSRF 형식을 검사한 뒤 프로젝트의 `.private/session.json`에 저장합니다. 기존 인증을 교체하기 전 검사를 완료하며 인증 값은 화면에 출력하지 않습니다. HAR 원문 전체는 복사하지 않습니다. **새 인증을 발급하는 기능이 아니라 본인이 이미 로그인해 받은 인증을 연결하는 기능**입니다.

- **Mac:** 기존과 같이 인증 파일 0600 / 전용 폴더 0700으로 보호합니다.
- **Windows:** [Windows DPAPI의 CurrentUser 보호](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata)로 암호화한 내용만 파일에 저장합니다. 암호화가 실패하면 평문 저장으로 전환하지 않습니다. 복호화는 인증을 연결한 Windows 사용자로 실행해야 합니다. Node의 Windows 파일 권한은 POSIX 0600과 같지 않으므로 단순 권한 검사 생략으로 처리하지 않았습니다.
- **다른 PC·운영체제로 이동:** 인증 파일은 옮기지 말고 각자 다시 로그인해 연결합니다. 원본 HAR는 별도로 암호화해 주지 않으므로 여전히 민감정보로 취급하세요.

### 인증 보관과 갱신

- 비밀번호를 이 프로그램에 입력하지 않습니다. 공식 사이트 로그인은 공식 사이트에서만 합니다.
- `.private/`, HAR, 쿠키, 인증을 포함할 수 있는 `research/`와 `.env*`는 다른 사람·GitHub·파일공유 사이트에 보내지 않습니다. 저장한 HAR도 로그인 권한과 같은 민감정보로 취급하고 필요 없어진 뒤 안전하게 삭제하세요.
- 같은 프로그램 폴더를 여러 계정이 공동 사용하지 않습니다. 각자 자기 컴퓨터와 사용자 계정에 별도 설치합니다.
- 만료 시 **숲나들e 다시 로그인 → 로그인 완료·연결**을 수행합니다. 사용자의 로그인 동작 없이 자동 갱신하거나 감지를 우회하지 않습니다.
- `FORESTTRIP_SESSION_FILE`을 별도로 지정한 고급 사용자는 해당 파일을 직접 관리합니다. 기본 로컬 연결 도구를 쓸 때는 이 설정을 해제합니다.
- 인증 값이 공개되었다면 파일 삭제만으로 충분하지 않을 수 있습니다. 해당 로그인 세션을 종료·갱신하고 공개된 저장소 이력도 확인해야 합니다.

## 자주 막히는 부분

- **인증 필요/로그인 만료:** 검색 화면의 다시 로그인 버튼으로 연결합니다. 인증 실패를 빈방 0개로 표시하지 않습니다.
- **개발자 도구 감지:** 정상 연결을 완료할 수 없는 경우입니다. 우회하지 않습니다. 현재 버전이 모든 환경에서 로그인만으로 바로 사용 가능한 것은 아닙니다.
- **화면 접속 안 됨:** 실행 창이 켜져 있는지 확인합니다. 같은 프로그램을 두 번 실행하지 않습니다.
- **Windows 인증 보호 실패:** 본인의 일반 Windows 사용자 계정으로 실행하는지, Windows PowerShell이 사용 가능한지 확인합니다. 보안 정책을 끄거나 평문 인증 파일로 바꾸지 않습니다.
- **Windows 종료 후에도 실행 중:** 정상 종료에는 Ctrl+C를 사용하세요. 프로그램은 자신이 띄운 프로세스 트리만 종료하며, 모든 Node 프로세스를 일괄 종료하지 않습니다.
- **예약 페이지 오류:** Chrome에서 사용하세요. Codex 내장 브라우저에서는 숲나들e 자체 오류 페이지가 나타난 사례가 있습니다.
- **업데이트 후 오류:** 기존 실행을 종료하고 `app`에서 `npm ci`를 실행한 뒤 다시 시작합니다. 실행기는 화면을 매번 다시 빌드합니다.
- **일부 조회 실패:** 확인한 범위만 표시됩니다. 전체 조회 완료와 구분하며 통신·응답 구조 오류를 빈방 없음으로 바꾸지 않습니다.

## 개발 실행과 검증

```sh
cd app
npm ci
npm run build
npm start
# 화면: http://127.0.0.1:3000
```

화면 자동 갱신이 필요한 개발에는 `npm run dev:local`을 사용합니다. 완성 빌드는 화면/API 3000과 내부 렌더러 3001, 개발은 화면 3000과 API 8788을 사용합니다. 모두 `127.0.0.1`에만 열리고 외부 Host/Origin을 거부합니다. 외부 공개 서버 설정은 제공하지 않습니다.

```sh
npm test
npm run lint
npx tsc --noEmit
npm run build
# 본인 인증과 실행 중인 프로그램이 있을 때만:
npm run test:live
```

단위 테스트의 기록 기반/오류 주입 자료는 운영 검색에 사용되지 않습니다. [실제 조회 구조 조사](docs/foresttrip-investigation.md), [인수 검증 기록](docs/acceptance.md)을 참고하세요. 인증/계정은 조사 자료와 함께 공유하지 않습니다.

`.github/workflows/local-platform-check.yml`에서 macOS/Windows의 설치·테스트·린트·타입 검사·빌드·완성 프로그램 실행을 검사합니다. [2026-09-09 자동 검사 결과](https://github.com/we-insub/supnadeuri/actions/runs/34325063072)는 양쪽 모두 성공했습니다.

- Windows: 테스트 43개 통과, 실제 DPAPI 암호화/복호화 포함.
- macOS: 테스트 42개 통과, Windows 전용 DPAPI 검사 1개만 건너뜀.
- 양쪽: 검색 화면 HTTP 200, 인증 미연결 상태, 외부 요청 출처 차단, 잘못된 검색 조건 거부 확인.
- 사용자 인증을 CI에 넣지 않고 숲나들e 실조회도 수행하지 않습니다. 자동 검사 성공이 현재 빈방·로그인 유효성을 보장하지 않습니다.

**최근 실조회 재검사:** 2026-09-09 16:41 KST, 이 Mac에 저장된 기존 인증으로 조회했으나 원본 HTTP 403으로 실패했습니다. 인증 만료 또는 접근 제한을 구분해서 확정하지 않았으며 재시도·우회하지 않았습니다. 앞서 성공한 실조회 기록과 별개로, 현재 실조회 재검증에는 본인 재로그인 및 인증 재연결이 필요합니다. 접근 제한이 계속되면 중단하세요.

## 검색 구조와 범위

수집(`app/server/upstream.mjs`) → HTML/JSON 검사(`parsers.mjs`) → 정규화(`normalize.mjs`) → 검색 API(`search.mjs`, `index.mjs`) → React 화면 순서입니다. 화면을 원본 HTML에 직접 결합하지 않았습니다.

예약 데이터 수집은 계속 HTTP 요청입니다. `playwright-core`는 사용자가 요청한 전용 Chrome 로그인 창에만 사용하며 빈방 크롤러로 사용하지 않습니다. 외부 API 신청·공용 계정·Chrome 확장프로그램은 추가하지 않았습니다.

`POST /api/search` 입력 예:

```json
{"check_in":"2026-09-19","check_out":"2026-09-20","guests":2,"regions":["경기","강원"]}
```

전국은 `regions:[]`입니다. 일반예약 가능한 숙박 객실만 반환하고 야영·예약 대기는 제외합니다. 전체 기간 목록에 포함된 동일 객실에 대해 모든 숙박일·정원·가격 합계를 검사합니다. 상세 요금만으로 빈방 여부를 판단하지 않습니다.

휴양림은 공식 ID로 묶고 객실별 유형·이름·정원·가격·공식 링크는 유지합니다. 필터 적용 후 가격 정렬과 표시 개수도 갱신합니다. 가격은 전체 숙박기간 합계이며 추가 인원 요금 대상은 별도 안내합니다. 최종 요금·주차·입장료·할인은 공식 예약에서 확인합니다.

예약 버튼은 해당 휴양림 공식 예약 입력 페이지로 연결됩니다. 날짜와 객실을 공식 사이트에서 다시 선택해야 할 수 있습니다. **예약·결제는 대행하지 않습니다.**

현재 원본 소재지의 `전남광주통합특별시` 표기는 `전남·광주`로 정규화합니다. 양평설매재 사무국 주소 오류는 공식 홈페이지 근거로 보정합니다. 확인되지 않은 소재지는 임의 분류하지 않습니다.

## 원본 요청 제한과 장애 확인

- 원본 동시 요청 3개, 시작 간격 250ms, 요청 제한시간 12초, 네트워크/5xx 최대 1회 재시도.
- 401/403 재시도 안 함, 429는 Retry-After 대기. 검색 전체 제한시간 180초.
- 동일 조건 60초 캐시, 최대 10조건. 진행 중 동일 조건 병합, 다른 조건 동시검색은 혼잡 안내.
- 부분 실패는 `complete:false`로 표시합니다. HTTP 상태, 파싱 오류, 응답 구조 변경과 마지막 성공 시각을 인증 비밀 없이 기록합니다.
- `GET /api/health`는 파일 연결 여부 및 마지막 성공 상태를 보여줍니다. 재시작 시 캐시·기록 상태가 초기화됩니다.
- 각자 실행하는 구조라 이용자 전체의 원본 요청량을 중앙에서 제어하지는 못합니다. 무인 반복조회·대량 수집용으로 사용하지 마세요.

## GitHub 공유 안내

코드와 이 사용법만 공유합니다. `.gitignore`는 프로젝트와 `app/` 양쪽에 있으며 `.private/`, `research/`, HAR·세션·쿠키·환경설정·개인 키를 제외합니다. 이미 추적된 파일은 제외 규칙만으로 제거되지 않으므로 커밋 전 `git status --short`, `git diff --cached --name-only`를 확인하세요. `git add -f`로 인증 파일을 강제 추가하지 않습니다.

[GitHub 저장소: we-insub/supnadeuri](https://github.com/we-insub/supnadeuri)에 소스와 사용법을 공개했습니다. 누구나 확인하고 내려받을 수 있으며, 인증 파일은 업로드하지 않았습니다. 공용 웹사이트 배포, 계정 공유, 자체 회원가입, 취소 알림, 타 플랫폼, AI 추천은 이번 버전에 포함하지 않습니다.

[공식 로그인](https://www.foresttrip.go.kr/com/login.do)으로 사용자가 받은 인증을 활용하는 로컬 도구입니다. 실제 수집 가능 여부는 원본 사이트 정책과 세션 상태에 따라 달라집니다.
